## Decisions already locked in (from the frontend spec, 2026-11-11)

- Endpoint contract, locked in exactly as proposed (updated 2026-11-11 for the Owner field set below):
  - `GET /api/v1/marts` → `200` `[{ id, name, code, status }]`.
  - `POST /api/v1/marts` `{ martName, ownerFirstName, ownerLastName, ownerEmail, ownerContact, ownerCnic }` → `201` `{ martId, martCode, ownerStaffId, setupCode }` on success; `400` `{ errors: { martName?, ownerFirstName?, ownerLastName?, ownerEmail?, ownerContact?, ownerCnic? } }` (per-field messages) when a field is missing or fails validation; a generic error on any other failure.
- Both endpoints are Super Admin-only (same session cookie mechanism as Story 1.2); the Super Admin API never exposes a Mart's sales, stock, staff activity or Audit Log — only `{ id, name, code, status }`.
- **Owner field set (updated 2026-11-11):** First name, Last name, Email, Contact (phone), CNIC — replaces the earlier single "Owner name"/"Owner contact" fields. The frontend validates format (not just required) for Email, Contact and CNIC before sending; the backend should still validate independently (never trust client-side validation) and return the same per-field error shape on any failure, including a malformed CNIC/Email/Contact that somehow reaches the API. CNIC is a Pakistani CNIC, canonical shape `NNNNN-NNNNNNN-N` (13 digits with dashes after the 5th and 12th digit) — decide whether to store with or without dashes (store normalized, e.g. digits-only, is usually simplest; re-format for display only).
- Creating a Mart produces: a unique 6-character Mart code (letters and digits, never `0`, `O`, `1` or `I`), an Owner account with a Mart-unique numeric Staff ID, and a one-time setup code (used once, with an expiry).
- One Owner per Mart, holding every Permission; the Owner's Role can never be edited down (per epic-1-context.md — Roles/Permissions themselves are an Epic 2 concept, but this constraint is recorded now since the Owner account is created here).
- Every Super Admin "create Mart" action goes to the platform audit log (separate from each Mart's own Audit Log), per epic-1-context.md.
