- (note) Current setup: server-room desktop w/ retail desktop app; manager keys supplier receipts (name, serial/barcode, qty) into inventory; counter POS with barcode scanner; cart held locally, stock deducted only on payment
- (direction) Proposed: mobile-first web app, all data in cloud instead of local hard drive (corruption risk)
- (assumption) Local-hard-drive corruption is the main pain driving the change (unverified)
- (assumption) Internet at the Mart is reliable and can be upgraded to higher bandwidth
- (decision) Hard requirement: the counter must never stop selling
- (crack) Reliable internet and never-stop-selling conflict unless counter works offline; offline-first with sync is implied but not yet decided
- (decision) Offline-capable counters required (consequence of never-stop-selling); sales are additive events, stock = received - sold, so no sale conflicts
- (decision) Negative or mismatched stock is surfaced as an exception report for the manager, not a conflict to resolve
- (decision) Non-additive data (prices, product edits): cloud copy is authoritative, counters pick up on sync
- (note) Receiving: sealed cartons trusted by label qty, opened cartons counted; no routine shelf counts; shrinkage invisible today
- (decision) Products have unit hierarchy carton -> pack -> unit with conversion; items are prepackaged (1kg oil/surf), milk in packs
- (assumption) No loose items sold by weight (unconfirmed)
- (decision) Mobile-first means responsive web: owner/manager add stock and monitor from anywhere; server-room desktop with USB scanner for speed; phone camera scanning also supported
- (lock) Counter and server-room desktop use USB scanner for speed; phone is secondary entry and monitoring surface
- (kill) Remote stock entry from outside server room (both earlier ideas) dropped from v1; phone is read-only
- (decision) Roles: cashier sells only (refund/void needs manager approval); manager/owner edits stock/products/prices only from registered devices (server-room PC from day one, owner can register more); admin/owner views stats read-only on phone from anywhere
- (decision) Every stock, price, user change is audit-logged with who and when
- (decision) v2 candidate: phone receiving with owner approval
- (assumption) Old desktop app stores inventory/history as files or CSVs that can be imported (guess, unverified - must inspect real files)
- (decision) Cutover: import existing catalog, then one full physical stock count so cloud starts accurate
- (direction) Existing-data migration deferred; build for fresh start; data model must support bulk import later
- (decision) Payment methods: cash and card only; system records payment type, does not process card payments (separate terminal) - assumed
- (assumption) Receipts printed on thermal printer; returns need manager approval and restock - unconfirmed
- (decision) Receipts printed on thermal printer
- (decision) Returns: cashier handles at counter with no manager approval; item restocked. Supersedes earlier approval assumption
- (crack) Unapproved returns allow cashier refund abuse and restocking damaged goods; mitigation: returns logged and shown in admin exceptions report
- (lock) v1 success criteria, all four equally important: counter never stops selling; faster receipt entry; stock matches shelf; owner checks sales on phone
- (direction) Recommended build order: offline counters, receiving, stock accuracy and counts, phone dashboard (dashboard can slip first)
- (lock) Only the single unit has a barcode; cartons/packs have none. Receiving is by carton/pack count with per-product conversion to units; cashiers scan single units only
