Cloud POS + Inventory for a Mart

Forge report · 2026-10-05 · Outcome: hardened

The idea

Replace the Mart's single server-room desktop retail app with a cloud, responsive web POS and inventory system. Today a manager keys supplier receipts into the desktop, counters scan with USB barcode scanners, and stock is deducted when payment is made.

Locked decisions

  • The counter never stops selling. Counters work offline and sync later. This is a hard requirement.
  • Sales are additive events. Stock = received − sold, so sales never conflict. Mismatched stock goes to an exceptions report. Price and product edits: the cloud copy wins.
  • Roles. Cashiers sell only. Manager/owner edits stock, products and prices only from registered devices (the server-room PC from day one). Admin/owner views stats read-only on a phone. Every change is audit-logged.
  • Devices. Counter and server-room desktop use USB scanners. The phone is a read-only dashboard. "Mobile-first" means responsive web.
  • Products. Per-product carton → pack → unit conversion. Only single units carry barcodes. All items are prepackaged.
  • Payments and receipts. Cash and card, recorded only. Thermal receipt printer.
  • Returns. Handled by the cashier at the counter with no approval; the item is restocked.
  • v1 success, all equal. Never stops selling · faster receipt entry · stock matches shelf · owner checks sales on phone.
  • Build order. Offline counters → receiving → stock accuracy and counts → phone dashboard.

Rejected, and why

  • Remote stock entry and phone-camera scanning. A stolen phone or password could alter inventory, and receiving is physical anyway. Phone receiving with owner approval is a v2 candidate.
  • Manager approval for returns. The owner chose speed at the counter.
  • Deferred, not rejected: weighed items, card payment processing, and import of existing data.

Weak points that survived

  • Offline sync is the largest build risk.
  • Old app data is unverified. Its format is unknown. The data model must support bulk import, and cutover needs one full physical stock count.
  • Unapproved returns allow refund abuse and restocking of damaged goods. Mitigation: returns per cashier appear in the admin exceptions report, which only helps if the owner reads it.
  • Unconfirmed assumptions: hard-drive corruption is the main pain; no weighed items; internet is reliable.
  • Shrinkage (theft, damage, expiry) stays invisible without regular spot counts.
